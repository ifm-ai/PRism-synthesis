The current configuration rendering does not produce the expected line for a custom output command. Users need a `CustomOutput` instance, when included in a model configuration that inherits from the library's base `RV` class, to be emitted as a single line that begins with a colon, followed by the command name and its arguments separated by a fixed amount of whitespace. The public API must allow creating a `CustomOutput` with the fields `time_per`, `stat`, `variable`, and `space_agg`. When such an instance is placed in a sequence field of an `RV` subclass (using the alias `CustomOutput`) and the model's `to_rv()` method is called, the resulting string, after any surrounding whitespace is stripped, must be exactly the literal line `:CustomOutput         YEARLY AVERAGE PRECIP ENTIRE_WATERSHED`. No additional characters, different spacing, or missing colon are acceptable. The implementation should expose this behavior through the existing public classes without requiring changes to the test code.
