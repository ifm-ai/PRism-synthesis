Flux models in the library currently only accept LoRA weights that follow the native Diffusers naming and scaling conventions. Users who have LoRA checkpoints produced by the popular Kohya training scripts or by XLabs encounter loading errors because those checkpoints use a different key layout and scaling strategy. The missing capability is an automatic conversion step that recognises these external formats, rewrites their parameter names, and applies the correct scaling so that the weights can be merged with a Flux model without manual intervention. 

The implementation must extend the LoRA loading pipeline to inspect the keys of a provided checkpoint. If any key matches the pattern used by Kohya (e.g., contains a "lora_down.weight" suffix), the loader should treat the checkpoint as a Kohya‑style Flux LoRA, convert the down‑ and up‑weights to the internal representation, and respect the alpha values stored in the file. The conversion must also recompute the scaling factor (alpha divided by rank) and adjust the weight tensors accordingly, preserving the original effect of the LoRA when applied. When the checkpoint follows the XLabs convention (identified by the presence of a "processor" token in its keys), a separate conversion path should be taken that maps the XLabs naming scheme to the internal one; XLabs checkpoints do not carry explicit alpha values, so the loader should simply perform the name translation without attempting to return alphas. In both cases the resulting state dictionary must be compatible with the existing Flux LoRA merging logic, and the loader should continue to support the previously‑implemented generic non‑Diffusers conversion for any other formats. 

The new behavior should be transparent to end‑users: they can pass a path to a Kohya or XLabs LoRA file to the Flux pipeline's `load_lora_weights` method (or equivalent entry point) and the library will automatically perform the appropriate conversion, returning either a tuple of (state_dict, alphas) for Kohya or just the state_dict for XLabs, matching the signature of the existing loader. Errors should be raised only if the checkpoint cannot be recognized as any supported format, preserving the original error handling for unknown files.
