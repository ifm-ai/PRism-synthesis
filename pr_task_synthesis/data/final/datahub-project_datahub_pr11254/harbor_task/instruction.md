When the Snowflake ingestion source processes a table, it must read the column named `CLUSTERING_KEY` from the query results. If the column value is non‑null, the ingestion code should add a custom property to the dataset's `datasetProperties` aspect with the key `CLUSTERING_KEY` and the exact string value from the query (e.g., `LINEAR(COL_1)`). The resulting JSON work unit must contain a `customProperties` object that includes the entry `{ "CLUSTERING_KEY": "LINEAR(COL_1)" }` for each table that has a clustering key. For tables where the `CLUSTERING_KEY` column is null or missing, the `customProperties` object must be empty. Views or other non‑table objects must never receive this property. The change must not alter any other fields in the emitted metadata, such as `externalUrl`, `name`, or `qualifiedName`. The test suite validates this behavior by providing mock query results where every table includes `"CLUSTERING_KEY": "LINEAR(COL_1)"` and by comparing the generated JSON against golden files that expect the exact `customProperties` mapping described above.
