When the agent starts, it gathers information about container images from the containerd runtime. An individual image can be known by several different references – for example a raw image ID, one or more repository tags, and one or more repository digests. The previous implementation emitted a separate metadata event for each reference, which resulted in duplicate entries and sometimes incomplete information because some fields (such as the repository digest) were missing on the first reference. The required behavior is to collect all references that belong to the same underlying image (identified by the image's manifest digest) and emit a single metadata event that contains the complete set of tags and digests. In addition, the event should include a user‑friendly name for the image: prefer a repository digest if available, otherwise a repository tag, and fall back to the raw image ID only when no other name exists. If an image already exists in the metadata store, its name should be updated only when the newly selected preferred name is more readable (i.e., does not contain a raw sha256 string). The aggregation and notification must happen during the initial image collection phase, and the notification should be sent exactly once per unique image after all its references have been merged. Errors while retrieving an image's manifest should be logged and the particular image skipped, without aborting the whole collection process. The logic should respect the configuration flag that enables or disables image metadata collection, performing no work when the feature is turned off.
