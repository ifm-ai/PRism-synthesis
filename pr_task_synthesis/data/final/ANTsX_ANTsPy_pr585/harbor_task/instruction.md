The library currently warps images using double precision only. Users need a way to request single‑precision (float32) computation for large 4‑D datasets without changing the type of the returned image. Implement a new boolean parameter `singleprecision` on the high‑level `apply_transforms` function, defaulting to `False`. When `singleprecision` is `True` the underlying transformation should be performed in single precision, but the function must still return an ANTsImage whose `pixeltype` exactly matches the `pixeltype` of the supplied moving image. The returned image must also preserve the physical space of the fixed image (origin, spacing, direction) so that a call to `ants.ants_image.image_physical_space_consistency(fixed, warped, 0.0001, datatype=False)` returns `True`. The function must continue to raise an exception if an unknown interpolator name is supplied or if any file listed in `transformlist` does not exist. Tests verify that (1) the `pixeltype` of the warped image equals the moving image’s `pixeltype` for both the default double‑precision call and the `singleprecision=True` call, (2) physical space consistency holds within a tolerance of `0.0001`, (3) the sums of the double‑precision and single‑precision warped images are almost identical (`assertAlmostEqual(..., places=3)`), and (4) error conditions raise exceptions. The implementation should only expose the new argument and maintain existing validation logic; internal cloning, command‑line flag handling, and data‑type conversion are free to be designed as needed.
