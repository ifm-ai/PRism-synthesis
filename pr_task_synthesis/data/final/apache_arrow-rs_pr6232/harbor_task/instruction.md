When reading column data from a Parquet file, the reader iterates over pages and extracts repetition levels, definition levels, and values. In a well‑formed file each page provides a positive number of repetition levels, which the loop uses to make progress. However, if a file is corrupted and a page reports zero repetition levels, the loop continues without consuming any input, leading to an endless cycle that never returns control to the caller. The required behavior is to detect this situation early and abort the read operation with a clear error, rather than looping indefinitely. The implementation should examine the counts returned from the low‑level repetition‑level decoder on each iteration; if both the number of records read and the number of repetition levels read are zero, the reader must raise an error indicating that insufficient repetition levels were obtained. This check should be performed before any further processing of the page, ensuring that the caller receives a deterministic failure instead of hanging. The error message should be user‑friendly and convey that the Parquet column appears to be malformed or corrupted. No changes to the public API are required; the fix is internal to the column‑reading logic but must be observable through the termination of the read operation with an error rather than an infinite loop.
