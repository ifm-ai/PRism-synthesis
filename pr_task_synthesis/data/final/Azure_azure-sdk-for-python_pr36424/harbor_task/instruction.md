Finetuning job objects must accept the `task` argument in camelCase form (e.g., `"chatCompletion"`, `"textCompletion"`) and correctly translate it to the SDK's internal snake_case representation used by the REST model. When a user creates an `AzureOpenAIFineTuningJob` or `CustomModelFineTuningJob` with a camelCase task string, the object should be considered valid and its method that produces a `RestFineTuningJob` (or equivalent REST payload) must contain the task value in snake_case (e.g., `"chat_completion"`, `"text_completion"`). If the supplied task string is not one of the predefined supported identifiers, the constructor must raise a validation error. The conversion must happen both on object construction and when serializing back to the REST model, ensuring that downstream service calls receive the expected snake_case value. No other behavior of the job objects should be altered.
