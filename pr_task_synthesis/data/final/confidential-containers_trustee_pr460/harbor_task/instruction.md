The IBM Secure Execution verifier currently always validates the X.509 certificate chain when processing attestation requests, except when compiled in debug mode where a special flag can be used. This makes it impossible to run the verifier in production or release images without performing the verification step, which is sometimes required for development environments where the full certificate infrastructure is not available. The missing capability is a runtime switch that allows users to disable certificate verification regardless of the build type.

Implement a configurable behavior that reads an environment variable named `SE_SKIP_CERTS_VERIFICATION`. When this variable is present and its value can be parsed as a boolean true, the verifier must skip the entire certificate verification process and proceed as if the certificates were valid. In all other cases – when the variable is unset, empty, or cannot be parsed as true – the verifier should perform the normal verification using the configured root CA certificates and CRLs. The default behavior must remain verification enabled.

The change should be observable through the verifier's response: with verification enabled, an invalid or missing certificate should cause the request to fail with an appropriate error; with verification disabled via the environment variable, the same request should succeed, returning a valid attestation challenge. This toggle must work in both debug and release builds, ensuring that developers can use the same image for testing without needing separate debug binaries. The implementation must not alter any other functionality, and any parsing errors of the environment variable should be treated as a false value, preserving the secure default.
