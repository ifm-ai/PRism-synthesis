The CNSGAGenerator must keep its internal population DataFrame at exactly the configured `population_size` (e.g., 32) regardless of how data is added or evaluated. When `generate(n)` is called, it should return a DataFrame containing `n` new candidate rows. When `evaluate_data(df)` is invoked on any subset of those rows (including multiple calls with slices of the same generation), the generator must incorporate the evaluated rows and, if necessary, trim or replace individuals so that the total number of rows never exceeds the configured limit. The generator must also expose an `add_data(df)` method that can accept an external DataFrame whose index values may be non‑unique (e.g., all indices set to the same integer). Adding such a DataFrame must not cause the population to grow beyond the limit; the implementation should rely on positional indexing rather than label‑based `.loc` selection to avoid selecting multiple rows for a single index label. After a sequence of operations—including many calls to `generate`, chunked evaluations, and repeated additions of duplicate‑index DataFrames—the length of `generator.population` must remain exactly `population_size`. No exceptions, warnings, or errors related to duplicate indices should be raised during these operations, and the generator should continue to produce valid candidate rows for subsequent steps.
