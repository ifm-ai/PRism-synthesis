The continuous‑integration pipelines for LightGBM install the freshly built Python package using `pip install --user`. In the hosted runner environment, the user‑site directory (e.g., `/github/home/.local/lib/pythonX.Y/site-packages`) is mounted from the host and therefore persists across separate CI jobs. When a later job (such as the CUDA 11.8 wheel build) runs, pip sees a previously installed copy of the package and skips reinstalling the newly built wheel, assuming the required version is already satisfied. This leads to two observable problems: the test suite may import an older build that was compiled with a different CUDA version, and runtime errors appear because shared libraries like `libomp.so.5` are not present in the stale environment.

The required behavior is that each CI job installs the LightGBM wheel or source distribution into the isolated Conda environment created for that job, not into the persistent user‑site location. Consequently, pip should always reinstall the exact artifact produced in the current job, and the Python interpreter used in the tests should load the freshly installed package from the job‑specific `site-packages` directory. This ensures that the correct CUDA, GPU, MPI, or other optional components are present and that no leftover files from previous jobs interfere with the current run.

To achieve this, all invocations of `pip install` within the CI scripts (both the Bash `.ci/test.sh` and the PowerShell `.ci/test_windows.ps1`) must be changed to omit the `--user` flag. Additionally, any wrapper scripts that perform a `build-python.sh install --user` step should be updated to call the install command without the `--user` option. The scripts should continue to pass through any other required arguments (such as `--mingw` or configuration settings) but rely on the active Conda environment to determine the installation target. After these changes, each CI job will have a clean, self‑contained Python environment, eliminating the cross‑job contamination and the associated import errors.
