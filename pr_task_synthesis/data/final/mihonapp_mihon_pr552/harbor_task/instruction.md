When the application saves a page image to the device, it records the modification time in the media database. The current implementation stores this value in milliseconds since the epoch, but the Android documentation specifies that the DATE_MODIFIED column expects the time in seconds. On certain devices, such as Samsung phones using the Gallery app, the millisecond value is interpreted as seconds, resulting in dates that appear far in the future (e.g., the year 56189). This leads to confusing file metadata and can break features that rely on correct timestamps.

The required behavior is that, after an image is saved, the DATE_MODIFIED entry in the media store reflects the current time expressed in seconds, not milliseconds. The timestamp should be accurate to the second and should be compatible with the expectations of all Android devices, including those that previously mis‑interpreted the value. No other metadata or file‑saving logic should be altered; the change must be limited to the unit of the timestamp used for the DATE_MODIFIED field. The solution should continue to work on all supported Android versions, preserving existing functionality for devices running versions prior to the scoped storage model.

The observable effect is that, after saving an image, querying the media store for the DATE_MODIFIED value should return a number that, when interpreted as seconds since the Unix epoch, corresponds to the actual save time. On devices that previously displayed erroneous future dates, the displayed date should now be correct. All other aspects of the image‑saving process, such as file location, naming, and MIME type handling, must remain unchanged.
