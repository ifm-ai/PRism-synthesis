The Bioconda repository provides pre‑compiled bioinformatics tools for a variety of platforms. Currently the allelecount package can be built for the standard Linux‑64 architecture but fails to produce a package for the newer ARM‑based Linux platform. Users running on ARM servers or cloud instances therefore cannot install or run the tool via Conda. The required change is to make the recipe capable of building on the linux‑aarch64 architecture, while preserving the existing functionality on other platforms.

The solution must ensure that the build script invokes the compilation step with parallelism based on the available CPU count, so that builds complete efficiently on multi‑core ARM machines. The recipe metadata should be updated to declare that the built package can be used on the additional platform, and to provide proper licensing information, including the SPDX identifier and a reference to the license file. In addition, the package should expose a run‑exports entry that pins the package version according to standard semantic‑versioning rules, allowing downstream recipes to depend on a stable version range.

When the updated recipe is used, a user should be able to run `conda install cancerit-allelecount` on a linux‑aarch64 system, have the package compile without errors, and obtain an executable that responds to the `-h` help flag in the same way as on other platforms. The package metadata must list the new platform under the "additional‑platforms" section, and the license fields must correctly reflect the GPL‑3.0‑only license with a reference to the accompanying license file. All existing tests that invoke the help command should continue to pass, confirming that the binary is correctly installed and functional.
