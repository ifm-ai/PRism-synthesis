The library provides several custom TensorFlow layers that compute persistent homology for different filtrations (cubical, lower‑star simplex tree, Vietoris‑Rips, and various perslay weight and phi layers). These layers were originally instantiated by calling the base Keras Layer constructor with a `dynamic=True` argument. In recent TensorFlow releases this argument is no longer accepted, causing the construction of the layers to raise an exception and preventing any downstream model from being built. The required behavior is that a user can create any of these layers without error on both old and new TensorFlow versions, and that the layers continue to produce the same persistence diagrams and weight calculations as before.

Implement the change by adjusting the constructors of all public TensorFlow layer classes so that they call the superclass initializer without specifying the `dynamic` flag. The default behavior of the base class should be used, which is compatible with all supported TensorFlow versions. No other functional changes are needed; the layers must still accept the same parameters, store them, and compute persistence diagrams, weight functions, and permutation‑invariant reductions exactly as they did previously. After the modification, creating an instance of any of these layers should succeed, and invoking the layer on appropriate input tensors should yield the same output shapes and values as before the fix.

The solution should be applied uniformly across all affected layer classes, ensuring that the library’s public API remains unchanged apart from the removal of the deprecated argument. This will restore compatibility with newer TensorFlow releases while preserving existing functionality for users performing topological data analysis within TensorFlow models.
