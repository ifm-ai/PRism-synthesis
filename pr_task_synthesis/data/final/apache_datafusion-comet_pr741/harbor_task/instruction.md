DataFusion Comet currently promotes Decimal128 values to Decimal256 for a number of arithmetic operations (addition, subtraction, multiplication, modulo, and division) regardless of the actual precision required for the result. This extra promotion incurs significant overhead, especially when the input decimals have small precision that comfortably fits within the 38‑digit limit of Decimal128. The desired behavior is to keep the computation in the Decimal128 domain whenever the resulting precision does not exceed the maximum allowed for Decimal128, only falling back to Decimal256 when the precision would overflow. For division, the implementation should also choose a fast 128‑bit integer path when the intermediate scaling factors stay within the Decimal128 precision bound, and only use arbitrary‑precision arithmetic when they would exceed that bound. The observable effect is that operations on low‑precision decimals produce the same numeric results as before but execute faster, while high‑precision cases continue to be handled correctly by promoting to Decimal256. Users should see no change in query results, but performance benchmarks for decimal arithmetic on small‑precision columns should improve noticeably.
