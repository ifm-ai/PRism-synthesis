When configuring a BigDLLM instance, users can pass a flag named `optimize_model` to control whether the underlying BigDL model should apply its internal optimizations. The intended behavior is that, if a caller explicitly sets `optimize_model=False`, the model will be loaded without those optimizations, while the default should remain `True` when the flag is omitted. Currently, the initialization routine removes any unknown keyword arguments before it checks for the presence of `optimize_model`, causing the flag to be lost and the model to always be loaded with optimizations enabled, regardless of user intent. This discrepancy leads to unexpected performance characteristics and makes it impossible for benchmark harnesses to disable the optimization for testing purposes.

The required change is to ensure that the value supplied for `optimize_model` (and similarly for `use_cache`) is retained and consulted when constructing the underlying model. The initialization logic should first capture these specific flags from the incoming arguments, apply sensible defaults when they are not provided, and then pass the resulting configuration to the model loader. As a result, a user who invokes the class with `optimize_model=False` should see the flag propagated to the underlying model, while callers who omit the flag should receive the default optimized behavior. The solution must preserve existing handling of other unrelated arguments and continue to set a default for `trust_remote_code` if not supplied.
