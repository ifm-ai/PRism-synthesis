The platform currently grants a member‑level IAM role a set of AWS permissions that are either overly broad, duplicate other entries, or missing actions required for creating and configuring VPCs used by the data platform. This leads to two issues: members have permissions that are unnecessary or invalid (e.g., a wildcard Cognito permission that does not correspond to any required service) and they lack the specific rights needed to fully provision and manage VPC resources such as route tables, network ACLs, flow logs, and VPC endpoint configurations. The required behavior is to adjust the policy so that it only includes the actions that are truly needed for member infrastructure work while removing any redundant or incorrect entries.

The updated policy must no longer contain the generic Cognito wildcard permission and must eliminate individual EC2 describe actions that are already covered by a broader EC2 describe wildcard. It should replace narrowly scoped EC2 VPC modification actions with a wildcard that covers all VPC modification operations, ensuring members can update VPC settings such as DNS configuration. Additionally, the policy must be expanded to include actions for associating and managing route tables, creating and deleting route tables, and handling network ACLs and flow logs, as these are required for the data‑platform‑compute VPCs. All other existing permissions should remain unchanged, and the policy should continue to deny any actions not explicitly allowed.

When applied, members should be able to create, modify, and delete VPCs and related networking components without encountering permission errors, while the removal of the invalid Cognito permission prevents unnecessary privilege exposure. The policy must still enforce a default deny stance for any actions not listed, preserving the principle of least privilege.
