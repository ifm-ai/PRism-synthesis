The library currently only supports Euclidean (L2) distance for IVF‑FLAT indexes. Extend the public API so that callers can specify a `distance_metric` when creating a dataset, ingesting vectors, and building an IVF‑FLAT index. The `distance_metric` argument must accept the string values "euclidean" and "cosine" (and reject any other value with a clear exception). When "cosine" is selected, the ingestion pipeline must automatically L2‑normalize every vector before it is stored. The index’s `query` method must return two NumPy arrays: `distances` and `ids`. For a cosine index, query vectors must be normalized internally and the returned distances must correspond to the cosine distance definition used by scikit‑learn’s `NearestNeighbors(metric="cosine")` (i.e., 1 – cosine similarity). The test helper `query_and_check` will call `index.query(queries, k=…, **kwargs)` and expects that the set of expected IDs is a subset of the first result row’s IDs, and, when an `expected_distances` array is supplied, that each returned distance for those IDs matches the ground‑truth distance within a relative tolerance of 1e-5 and an absolute tolerance of 1e-5. The implementation must also ensure that the index metadata records the chosen metric so that downstream code can read it, and that attempts to create an index with an unsupported metric raise an exception. All existing L2 functionality must remain unchanged.
