When an AnnData object's observation dataframe contains columns that are either a pandas Categorical with no defined categories, a pandas nullable integer extension (e.g., Int64) or a generic object column, and those columns consist entirely of missing values, the conversion pipeline must ensure that the resulting TileDB attribute is marked as nullable. The implementation must detect such columns during the pandas‑to‑Arrow conversion, replace their contents with a series of Python ``None`` values, and cast the series to the appropriate pandas extension dtype (string for generic object, categorical for Categorical, the matching nullable integer dtype for Int64). For columns that contain a mixture of null and non‑null values, the existing Arrow‑null handling must be preserved. After writing the Arrow table to a TileDB experiment via ``tiledbsoma.io.from_anndata``, opening the observation array with ``tiledb.open`` must expose attributes whose ``isnullable`` property is ``True`` for every column that originally contained any nulls, including the newly supported all‑null categorical, all‑null nullable‑integer, and partially‑null variants. Column names and ordering must remain unchanged, and no reliance on the internal ``pa.null`` sentinel for non‑numeric types is allowed; ``None`` should be used where appropriate. The solution must integrate with the existing ingestion workflow and satisfy the assertions in the test suite that check ``obs.attr("empty_categorical_all").isnullable``, ``obs.attr("empty_categorical_partial").isnullable``, ``obs.attr("empty_extension_all").isnullable`` and ``obs.attr("empty_extension_partial").isnullable``.
