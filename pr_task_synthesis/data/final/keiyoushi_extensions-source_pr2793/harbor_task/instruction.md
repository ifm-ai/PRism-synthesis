The Voyce.Me extension currently builds its network requests and UI links using an insecure HTTP scheme. This leads to mixed‑content warnings, possible request failures, and does not follow the site’s current requirement to serve content over HTTPS. The extension must be modified so that every reference to the site’s base address uses the secure URL "https://www.voyce.me". This includes the Origin and Referer headers sent with each request, any WebView button that opens the site, and any rate‑limiting configuration that depends on the host name. The change should be transparent to the rest of the code, which already works with path fragments that omit the domain, so only the scheme and host need to be updated.

In addition to the URL change, the extension’s published metadata must be updated. The version code should be incremented to indicate a new release, and the NSFW flag in the build configuration should be explicitly set to false (or the appropriate value) to reflect the content rating. These metadata adjustments must be reflected in the build script so that the extension is correctly identified by the host application.

From a user’s perspective, the extension should continue to function exactly as before: browsing popular titles, searching, and reading chapters should work without any change in UI or workflow. The only observable difference is that all network traffic now uses HTTPS, eliminating security warnings and ensuring compatibility with the site’s current configuration.
