ActiveAdmin's display helper must correctly identify boolean attributes using the model's attribute type registry rather than database column definitions. When the helper's `format_attribute` method is called with a model instance and an attribute name that is of type boolean—whether it is a real database column or a virtual attribute declared with `attribute :name, :boolean`—it must always produce a status tag. For a true value the output must be exactly ``<span class="status-tag" data-status="yes">Yes</span>\n``. For a false value it should render a similar tag with the label "No" and a `data-status` of "no". For a nil value the helper must render ``<span class="status-tag" data-status="unset">Unknown</span>\n``. This behavior must be applied consistently for all boolean attributes, including those that are nil, and must not depend on the older `columns_hash` detection. All other attribute types (strings, numbers, dates, collections, etc.) should continue to be formatted using the existing pretty‑formatting rules without change. The solution should expose no new public API; it only needs to ensure that `format_attribute` returns the correct HTML string for the described cases.
