Add support for persisting and reloading models quantized in the Marlin format. When a user calls `AutoGPTQForCausalLM.from_quantized` with `use_marlin=True`, the loader must produce a model whose sub‑modules include at least one instance of `MarlinQuantLinear`. The loader must also write a cached Marlin file on first load using the path returned by `auto_gptq.utils.marlin_utils._get_cached_marlin_save_name`, and that path must contain the substring `assets`. Subsequent calls to `from_quantized` with the same identifier must detect the cached file and load it directly, resulting in a load time that is less than 20 % of the initial load time measured in the same process. The model must expose a `save_pretrained` method that, when given a directory, writes a single `model.safetensors` file and a `quantize_config.json` file containing the boolean field `is_marlin_format` set to `true`. The older `autogptq_model.safetensors` file must not be created in this scenario. The implementation must ensure that after saving, reloading from the saved directory with `use_marlin=True` also satisfies the fast‑load timing constraint and yields a model with `MarlinQuantLinear` modules. All public interfaces (`from_quantized`, `save_pretrained`, `_get_cached_marlin_save_name`) must behave as described without relying on internal helper names or magic constants not asserted in the tests.
