The image processing library currently allows exporting images to the TIFF format, but it lacks the ability to control advanced TIFF features such as pyramidal layers and tiled storage. Users who need to generate multi‑resolution TIFFs for deep‑zoom viewers or want to optimise large images for random access cannot do so because the export API does not expose any parameters for these capabilities. This limitation forces developers to either post‑process the file with external tools or accept sub‑optimal performance.

The required change is to extend the public TIFF export configuration object with four new fields: a boolean flag to request a pyramidal TIFF, a boolean flag to request tiled storage, and integer values specifying the height and width of each tile. The defaults should preserve the existing behaviour: pyramidal and tiled modes disabled, and a sensible tile size (e.g., 256 × 256 pixels) when tiling is later enabled. When a caller sets these fields, the export routine must pass the corresponding values to the underlying libvips implementation so that the generated file reflects the requested layout. The rest of the export process – such as quality, compression, and predictor settings – should continue to work unchanged.

From a user perspective, the API now accepts an export parameter object where the new fields can be toggled and sized before invoking the TIFF save function. If the pyramidal flag is true, the resulting TIFF should contain a series of down‑sampled images forming a pyramid. If the tiled flag is true, the image data should be stored in tiles of the specified dimensions, enabling efficient region reads. When either flag is false, the file should be written as a standard, single‑resolution, scanline TIFF. Errors should be reported in the same way as before if the underlying libvips call fails.
