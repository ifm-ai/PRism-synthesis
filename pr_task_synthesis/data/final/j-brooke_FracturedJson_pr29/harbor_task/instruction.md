The formatter must expose a new setting called `NumberListAlignment` that lets callers choose how numeric values are aligned when they appear in JSON arrays or table‑like structures. The setting accepts four distinct modes: `Left`, `Right`, `Decimal`, and `Normalize`. In **Left** mode each number (or the literal `null`) is left‑justified within its column and padded with spaces on the right so that every column in the same row has the same width. In **Right** mode numbers are right‑justified and padded on the left. In **Decimal** mode the formatter aligns the decimal point (or exponent marker) of each numeric token, inserting spaces as needed so that all decimal points line up vertically across rows. In **Normalize** mode the formatter treats every numeric token as having a uniform length (including a fixed number of decimal places when appropriate) and pads `null` entries to the same width, guaranteeing that rows produced under this mode have identical character lengths. The formatter must apply the chosen alignment consistently to all numeric lists, regardless of nesting depth, and must respect other existing options such as line‑length limits, end‑of‑line style, and whitespace omission. The implementation is verified by a test suite that checks: (1) rows produced with `Normalize` have equal length, even when a row contains `null`; (2) the exact line‑by‑line output for `Left`, `Right`, `Decimal`, and `Normalize` matches the reference strings shown in the tests, including handling of large numbers, scientific notation, and negative values; and (3) the universal JSON test sets `NumberListAlignment` to `Decimal` and expects the formatted output to reflect decimal‑point alignment. No other behavior should change.
