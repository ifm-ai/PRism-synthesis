When a GIF file or data buffer is assigned to a LVGL GIF object, the library previously failed to populate the image descriptor with all required header information. This resulted in incorrect image dimensions, missing stride information, and the inability to treat the canvas as a regular LVGL image, causing rendering artifacts or crashes during animation. The fix must ensure that the GIF object's internal image descriptor is fully initialized with a valid header before the animation starts. Specifically, after loading a GIF, the descriptor's magic number, flags, color format, width, height, stride (bytes per line), and total data size must be set to values that reflect the actual GIF canvas (using ARGB8888 format, 4 bytes per pixel). The canvas pointer returned by the GIF decoder should be stored as the descriptor's data pointer. Additionally, any previously opened GIF must be cleanly closed and its cache entry dropped before a new source is loaded. The object's structure should hold an LVGL image descriptor rather than a generic draw buffer, allowing the rest of the image subsystem to treat GIF frames as normal images.

The observable behavior after the change is that calling the public function to set a GIF source on an object will result in a correctly sized, modifiable image that animates without visual glitches. The image will report the proper width and height, and the stride will match width multiplied by four bytes. The animation timer will operate on this correctly described image, and releasing or replacing the source will not leak resources. Errors such as "Couldn't load the source" should still be logged when the GIF cannot be opened, but successful loads must produce a fully described image ready for rendering.
