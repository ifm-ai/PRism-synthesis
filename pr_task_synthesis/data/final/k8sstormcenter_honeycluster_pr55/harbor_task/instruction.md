The repository contains a Kubernetes manifest for the STIX visualizer deployment. Integration tests expect that this manifest also defines a Service exposing the visualizer to other components in the cluster. Implement a change that adds a Service resource to the same YAML file (as a separate document following the existing Deployment). The Service must have `apiVersion: v1`, `kind: Service`, `metadata.name` set to `stix-visualizer`, and `metadata.namespace` set to `redpanda`. Its `spec.selector` must match the pod label `app: stix-visualizer`. The `spec.ports` list must contain a single entry with `protocol: TCP`, `port: 80`, and `targetPort: 3000`. The Service type must be `ClusterIP`. Ensure that the existing Deployment definition, including the environment variable `REDIS_KEY_PREFIX` with the value `"tetrastix"`, remains unchanged. The resulting file must be a valid multi‑document YAML file that can be applied with `kubectl` without errors. Tests will load the manifest and assert the presence and exact values of the Service fields described above.
