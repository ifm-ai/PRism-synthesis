The repository evaluation system must expose a top‑level boolean field named `restrict_user_defined_variables` to the Rego policy engine when processing GitLab repository data. This field should be populated from the `RestrictUserDefinedVariables` attribute of the `gitlab2.Project` struct contained in a `gitlabcollected.Repository`. If the attribute is present, its value must be used directly; if it is absent, the field must default to `true`. The policy identified by the name `overriding_defined_variables_isnt_restricted` must report a violation (i.e., cause the test to expect a failure) only when `restrict_user_defined_variables` is `false`. When the field is `true`, the policy must not report a violation. The test suite creates mock `gitlabcollected.Repository` instances with the `RestrictUserDefinedVariables` flag set to both `true` and `false` and invokes a helper that evaluates the policy `overriding_defined_variables_isnt_restricted` against the generated OPA input. It then asserts that a failure occurs exactly when the flag is `false`. Implement the data conversion layer and ensure the policy evaluation pipeline respects this contract so that the test `TestGitlabRepositoryRestrictsOverrideVariables` passes for both flag values.
