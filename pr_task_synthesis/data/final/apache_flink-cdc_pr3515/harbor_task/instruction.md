The CDC runtime must allow transform rules—both projection and filter expressions—to reference the same source column more than once. When a user adds a transform via `PostTransformOperator.newBuilder().addTransform(tableIdentifier, projection, filter)`, the `projection` string may contain repeated column names, for example `"col1, col2, col2 * col2 as square_col2"`. The operator must compile this expression without error, evaluate it for each incoming `DataChangeEvent`, and produce an output event that includes all columns in the order specified, with any computed columns correctly calculated (e.g., `square_col2` should equal `col2 * col2`). The `filter` string may also reference a column multiple times, such as `"col2 < 3 OR col2 > 5"`. The operator must evaluate the filter for each event and only emit a transformed event when the condition evaluates to true; events that do not satisfy the filter must be dropped (no output record). In the test scenario, a table with schema `col1 INT, col2 INT, square_col2 INT` and primary key `col1` is created. Inserting a row where `col2` is 2 should produce an output row with `square_col2` = 4, and inserting a row where `col2` is 6 should produce `square_col2` = 36. Inserting a row where `col2` is 4 should result in no output because the filter `col2 < 3 OR col2 > 5` evaluates to false. The operator must preserve the column order defined in the projection and must not create duplicate parameters or cause compilation failures due to repeated column references.
