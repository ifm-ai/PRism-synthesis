The library currently requires callers to pass owned std::string objects when querying information about pipeline inputs, operators, and feed counts. This forces unnecessary string allocations and copies, especially when the calls originate from the C API. The goal is to modernize the public query interfaces so that they accept a non‑owning string_view, eliminating temporary strings and improving performance. In addition, a new public function should be provided that, given the name of an operator, returns a pointer to the underlying operator object (or null if the name does not exist). All existing query functions that take a name—such as those returning reader metadata, input layout, dimensionality, data type, and the number of times an input should be fed—must be updated to accept string_view. The internal container that stores input operator descriptors should be changed to support heterogeneous lookup, allowing lookups with string_view without constructing a std::string. The observable behavior must remain the same: callers can still request the same information using the same textual names, but now they can pass any character span (e.g., a C‑string, std::string, or string literal) and receive correct results. If a name is not found, the functions should return the same error or sentinel values as before (e.g., null pointer for the operator retrieval, or appropriate error handling for the other queries). The changes must be reflected in the public API signatures, and the implementation must correctly handle the string_view arguments without altering the logical outcomes of the queries.
