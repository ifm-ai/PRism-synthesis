When a game uses several cameras that render to the same output surface while multisample anti-aliasing (MSAA) is enabled, the final image only contains the contributions from the first and the last camera. This happens because each camera keeps its own independent marker that indicates which of the two internal textures is currently being used as the main render target. As a result, after the first camera writes its data, the second camera forces a write‑back from the first texture and then switches to the second texture, and any subsequent cameras repeat the process, overwriting the work of the previous camera. The user therefore sees missing or incomplete rendering when more than two cameras share a target, which is a regression from earlier engine versions.

The required behavior is that all cameras rendering to the same logical target share a single piece of state that tracks which internal texture is active. When any camera finishes rendering, it should write back from the shared texture and then toggle the shared state so the next camera continues from the correct texture. This ensures that the write‑back and texture swapping logic works correctly regardless of how many cameras are involved, and that the final composited image contains the contributions of every camera. The solution must be transparent to the rest of the engine: existing APIs for setting a camera's target, enabling MSAA, and configuring render passes should continue to work unchanged, but the internal bookkeeping for the active main texture must be per‑target rather than per‑camera.

Implement this by adjusting the data structures that cache render‑target resources so that the active‑texture flag is stored in a cache keyed by the normalized render target (including HDR settings). All cameras that resolve to the same cache entry should reference the same flag. The change must not affect single‑camera scenarios or non‑MSAA rendering paths, and it should preserve thread‑safety and performance characteristics expected by the engine's rendering subsystem.
