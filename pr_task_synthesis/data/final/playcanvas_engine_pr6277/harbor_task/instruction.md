When running particle simulations that are processed on the CPU with the WebGPU backend, the engine currently fails to compile the vertex shaders. The failure is caused by two separate issues. First, the shader‑attribute extraction routine treats every "attribute" keyword it encounters as a new entry, even if the same attribute name appears more than once in the source. This results in duplicate‑attribute warnings and can abort shader creation. Second, the particle‑related vertex shaders always declare a set of high‑precision sampler uniforms that are only required for GPU‑based particle updates. When the CPU path is used, those samplers are never bound, leading to undefined‑uniform errors on WebGPU.

The required behavior is that the attribute extraction logic must recognize when an attribute name has already been recorded and simply ignore subsequent occurrences, emitting a non‑fatal warning instead of treating it as a new attribute. Additionally, the vertex shader code for CPU particles should only include the sampler uniform declarations when a compile‑time flag indicating a GPU particle simulation is active. When that flag is absent, the shaders must omit those uniforms entirely, preventing the engine from trying to bind textures that are not used.

With these changes, developers should be able to enable CPU particle simulations on the WebGPU platform without encountering shader compilation warnings or runtime errors related to missing texture bindings. The engine will continue to support GPU particle simulations as before, with the additional compile‑time flag controlling the inclusion of the relevant sampler uniforms.
